# 附近岗位搜索

根据用户指定的**岗位类型**，开启定位、从网络检索当前位置附近的招聘信息，并将结果保存到系统便签。

> Skill 负责理解需求与编排步骤；真正操作手机能力时，只调用本手册中的 MCP Tool，不要自造英文名。

## 何时使用

- 用户要找「附近 / 本地 / 周边」的工作、兼职、实习、招聘
- 用户给出岗位类型（如：咖啡师、仓管、前端工程师、家教）
- 用户希望把搜到的岗位记到便签里方便稍后查看

## 适合的提示词

用户可用下面这类说法触发本 skill（岗位类型可替换）：

**完整流程（定位 → 联网搜岗 → 存便签）**

- `帮我找一下附近的咖啡师工作，记到便签里`
- `用定位搜周边的外卖骑手招聘，结果保存到便签`
- `查一下我当前位置附近的 Java 实习，写进记事本`
- `附近有没有招服务员的？找完帮我记到便签`

**只找附近岗位（未提保存时，默认仍写入便签；用户说「不用保存」则跳过）**

- `帮我看看附近有什么仓管的工作`
- `搜一下本地的家教兼职`
- `周边前端工程师招聘有哪些`
- `我在附近想找一份兼职收银员`

**补充条件（半径 / 数量 / 全职兼职）**

- `找当前位置 5 公里内的快递员岗位，列 5 条就行`
- `本市范围内的测试工程师全职招聘，保存到便签`
- `附近周末能做的餐饮兼职，记到便签里`

**信息不完整（应先追问岗位类型再执行）**

- `帮我找附近的工作`
- `附近有什么招聘吗，记到便签`

收到后先问清岗位类型，再按标准流程执行。

## 必需信息

| 字段 | 说明 | 示例 |
|------|------|------|
| 岗位类型 | 用户输入的目标工种/职位；**不要猜测** | 服务员 / 外卖骑手 / Java 实习 |

可选（用户没说才用默认或再问）：

- 搜索半径：默认约 5–10 km，或「本市 / 本区」
- 结果数量：默认 5–8 条
- 是否写入便签：默认写入；用户明确说「不用保存」则跳过

岗位类型缺失时，先问清再继续，一次问完缺失项。

## MCP 工具（必须按此调用）

工具命名格式：`{provider}_{tool_name}`。本 skill 只用下面两个端上能力：

| 步骤 | Tool | 作用 |
|------|------|------|
| 定位 | `sysui_fast_location` | 调用 sysui 定位能力，获取/启用当前位置相关信息 |
| 保存 | `notes_create_note` | 把岗位摘要写入便签 |

`notes_create_note` 参数（以平台 Tool 描述为准）：

- `title`：笔记标题
- `content`：笔记正文
- `folder_id`：文件夹 ID（用户未指定时可省略或按平台默认）

**禁止**：编造未在能力手册中出现的 Tool 名；不要设计依赖「删除便签」的流程（`delete_note` 未开放）。

## 执行步骤

严格按顺序执行，不要跳步假装已定位或已保存。

### 1. 确认岗位类型

用一句话复述用户目标，例如：「帮你找当前位置附近的【服务员】岗位。」

若用户只说「帮我找附近的工作」而没有类型，先追问岗位类型。

### 2. 获取当前位置 → `sysui_fast_location`

1. 调用 **`sysui_fast_location`**（能力手册 · 系统开关 sysui）。
2. 若系统弹出定位/权限确认，等待用户同意后再继续；不要假设静默成功。
3. 根据工具真实返回结果解析位置（城市、区县、大致地址等）。
4. 若返回失败、定位未开启、或无法得到可用位置信息：
   - 如实说明原因；
   - 可请用户补充「所在城市/区县」后继续网络搜索；
   - **不能假装已经定位成功**。

### 3. 从网络检索附近岗位

岗位信息**必须来自网络实时检索**，不要用模型记忆编造公司名、薪资或链接。

1. 用当前位置 + 岗位类型构造搜索词，例如：
   - `{城市/区} {岗位类型} 招聘`
   - `{城市} {岗位类型} 附近 兼职/全职`
2. 优先覆盖公开招聘渠道（按可访问性选用）：BOSS直聘、智联招聘、前程无忧、本地生活/分类信息、企业招聘页、政府或高校就业网等。
3. 整理 **5–8 条**（搜到更少就如实说明），每条尽量包含：
   - 岗位名称
   - 公司/雇主
   - 工作地点（越具体越好）
   - 薪资（若有）
   - 任职要求摘要（一两句）
   - 信息来源与链接（若有）
4. 明显过期、与岗位类型不符、或不在附近范围的结果应过滤掉。

### 4. 向用户展示结果

使用简洁结构回复：

```markdown
## 搜索条件
岗位类型：服务员
位置：上海市 · 浦东新区（来源：sysui_fast_location）
范围：附近 / 本区

## 附近岗位
| # | 岗位 | 公司 | 地点 | 薪资 | 来源 |
|---|------|------|------|------|------|
| 1 | … | … | … | … | … |

## 说明
- 信息来自网络公开招聘页，以原页面为准。
- 投递前请自行核实公司与岗位真实性。
```

### 5. 保存到便签 → `notes_create_note`

在用户未拒绝保存时，调用 **`notes_create_note`**（能力手册 · 8.便签）：

- `title` 示例：`附近岗位 · {岗位类型} · {日期}`
- `content`：写入上方「搜索条件 + 岗位列表」的纯文本/Markdown 摘要（含来源）；不要只写一句「已找到工作」
- `folder_id`：仅在用户指定文件夹时传入

保存后根据工具返回如实告知：成功则说明已写入便签及标题；失败则说明原因，**不能回复「已经保存」**。

## 规则

- **先定位，再搜索，再保存**：顺序固定；任一步失败都要停在真实状态并说明下一步。
- **岗位类型来自用户**：不擅自扩大或更换工种；用户说「兼职服务员」就按兼职服务员搜。
- **岗位信息来自网络**：搜不到就说搜不到，并给出可手动打开的搜索思路；禁止编造岗位。
- **只用真实 Tool 名**：定位只用 `sysui_fast_location`，写便签只用 `notes_create_note`。
- **尊重权限弹窗**：定位相关确认需用户点同意。
- **不替用户投递**：只检索与记录；不自动注册账号、不代填简历、不声称已投递。
- **敏感与合规**：遇到明显传销、索要保证金等高风险信息要提醒用户谨慎。

## 快速示例

### 示例 A：类型明确 + 要求存便签

用户：`帮我找一下附近的咖啡师工作，记到便签里`

你应：

1. 确认岗位类型：咖啡师
2. 调用 `sysui_fast_location` 获取/启用当前位置
3. 按「{位置} 咖啡师 招聘」联网搜索并整理列表
4. 展示附近岗位表
5. 调用 `notes_create_note` 保存摘要，并告知保存结果

### 示例 B：带筛选条件

用户：`找当前位置 5 公里内的快递员岗位，列 5 条，保存到便签`

你应：

1. 确认：快递员、约 5 km、最多 5 条、需保存
2. 调用 `sysui_fast_location`
3. 联网检索并只保留约 5 km 内、最多 5 条
4. 展示结果后调用 `notes_create_note`

### 示例 C：缺岗位类型

用户：`帮我找附近的工作`

你应：先追问「想找什么岗位类型？」，拿到类型后再走定位 → 搜索 → 保存。
